A development process for small teams working with agents. Five stations, three points where you step in, and nothing to maintain by hand.

The line

Each token is an issue in your tracker that changes shape as it moves along. First you think, then you build. Skills to the right of the rail; you on the left.

Feature: several issues, one PR

When spec left a parent issue with sub-issues, feature takes the whole queue. It shows you the plan and how far it will go, you approve once, and then it chains one build per sub-issue without you having to say "continue".

Where everything lives

Each place has an owner and a lifecycle. Nothing is duplicated and nothing goes stale waiting for someone to update it.

Issue trackerThe state. Options, spec and the report of every run live as comments on the issue. When it closes, it is gone. Works with whatever tracker you use.
RepoThe code, the PRs and AGENTS.md: the one file every agent always reads, in any harness. It changes by PR like any other code.
Plugin factoryThe process. The skills for each station, with manifests for Claude Code, Codex and Cursor.

Factory rules

  • The agent decides the granularity. An issue can be one line or one page, whatever it takes.
  • Whatever needs your attention is shown in color: complexity, risk of breaking something, behavior changes.
  • One fresh session per issue. Context comes from AGENTS.md and the issue, never from a summary of earlier sessions.
  • Fast lane for small, clear ideas: from idea to spec without going through options.
  • The project defines the deploy, not the plugin.
  • No memory banks, no hand-maintained living docs, no run scoring. What is not used is not maintained.

Built for a solo dev or a team of 3 to 5: consistent, fast and cheap in tokens. Issue IDs and branch names on this page are examples.
